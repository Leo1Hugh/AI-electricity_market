# 交付协议（每次回复都必须遵守）

## 先判断模式

- **MODE=G**：你能读/写 GitHub 仓库。直接在指定分支提交、开 PR。
- **MODE=B**：你只能输出文本。按下面的 bundle 格式输出完整文件，由人类代提交。

在回复第一行写 **MODE=G** 或 **MODE=B**。

---

## MODE=G：GitHub 原生

1. 先读仓库根目录：AGENTS.md → docs/建模契约_v1.md → docs/协作协议.md → 你的任务书。
2. 确认基线 tag **contract-v1.0.0**；在 PR 里写你读到的 commit SHA。
3. 从 tag 开分支（分支名见任务书），只改任务书列出的文件。
4. 本地跑任务书里的 pytest 和 CLI；把真实输出贴进 PR。
5. push 分支，开 PR 到 main，标题 **[任务号] 一句话**。
6. CI 红就修，直到绿；不要用 skip 掩盖。
7. 不要合并 PR；Lead 合并。

---

## MODE=B：Bundle 文本

输出格式必须逐字如下（每个文件一个块，块之间不要有别的代码围栏）：

<<<FILE src/em/data/panel.py>>>
完整文件内容，从第一行到最后一行
<<<END>>>
<<<FILE tests/test_calendar.py>>>
完整文件内容
<<<END>>>

规则：

- 路径必须是仓库相对路径，只用正斜杠；禁止绝对路径、禁止 ..
- 只输出任务书允许的文件；不要输出 data/、reports/ 大文件。
- **不要省略**、不要写 "... 其余同上"、不要只给 diff。
- 如果一次回复放不下：在**文件边界**停止，最后一行写 **CONTINUE**；下一条从下一个文件继续。
- 代码块外只允许：MODE=B、必要的 ASSUMPTION/BLOCKED、最后的 HANDOFF。

---

## 每次结尾必须给 HANDOFF（不超过 15 行）

~~~text
## HANDOFF
- 完成：
- 未完成 / 阻塞：
- 关键假设：
- 自测命令与结果：
- 给 Lead 的风险提示：
~~~

## 发送前自检

- [ ] 每个文件都有开始和结束标记？
- [ ] 有没有 "..." / "略" / "同上" 偷懒？
- [ ] 是否只改了任务书允许的文件？
- [ ] 是否引用了不存在的列/函数/字段？
- [ ] 测试是否覆盖了"能推翻结论"的断言，而不是只跑通？
