| **W2（模型工）** | ChatGPT Plus 账号 B | 回测骨架、基线、L1 模型、集成、稳健性 | 不做数据管道、不改契约 |
| **Human（你）** | 仓库 owner | 建仓/授权、转发失败日志、拍板资源、最终提交 | 不需要读懂所有代码 |

### 为什么是这两个人

- **W1 是关键路径**：没有面板，W2 的模型无法在真实数据上验证。所以 W1 第一轮只做面板，不做"顺手"的特征扩展。
- **W2 可以解耦**：我提供 **make_synthetic_panel**，W2 在面板没合并前就能测 harness、metrics、模型接口。
- **第二轮换位**：W1 做完面板后转去做 **fetch_daily + 泄漏审计 + 提交脚本**；W2 继续模型。这样两条线始终都有活，且不抢同一个文件。
- **第三轮 W1 当红队**：W1 不碰模型，专门用独立路径挑战 W2 的结论（对偶/扰动/截断重算），符合"同轮对抗性验证"。

## 3. 上下文隔离：仓库是共享记忆

两个 ChatGPT 账号彼此看不到聊天记录，也不共享会话。解决办法不是"每次多贴一点"，而是把**所有会变的事实**放进仓库：

| 共享物 | 位置 | 谁维护 | 作用 |
| --- | --- | --- | --- |
| 契约 | docs/建模契约_v1.md + src/em/contracts.py | Lead | 字段、公式、API 的唯一真源 |
| 任务书 | docs/tasks/*.md | Lead | 一次只读自己那份 |
| 决策 | DECISIONS.md | Lead | 为什么这样定，避免重复争论 |
| 事故 | ERROR_LOG.md | 全员 | 踩过的坑 + 抓住它的不变量 |
| 看板 | docs/任务看板.md | Lead | 谁在做什么、卡在哪 |
| 代码/测试/结果 | GitHub PR | W1/W2 | diff、CI、评论都可审计 |
| 验收 | tests/ + CI | Lead | 不依赖人复述的自动裁判 |

**Prompt 只是"指针 + 快照"**：由 scripts/build_prompt.py 从上述文件生成，保证不会出现"聊天里说的和仓库里写的不一致"。

## 4. GitHub 交付流水线

~~~text
contract-v1.0.0 (tag)
   ├── w1/r1-panel   → PR #? → CI → Lead review → merge
   └── w2/r1-harness → PR #? → CI → Lead review → merge
~~~

规则：

1. **main 保护**：禁止直接 push；必须 PR + CI 绿。
2. **一个任务一个分支一个 PR**；PR 标题 **[W1-R1] panel builder**。
3. **CI 是裁判**：pytest -q；面板测试在 W1 合并前自动 skip，合并后必须绿。
4. **Lead 是唯一合并人**；W1/W2 不合并、不改 main。
5. **不能写 GitHub 的账号**：MODE=B 输出 bundle → 人保存到 inbox/ → scripts/apply_bundle.py 落盘 → 人提交。**这是降级路径，不是主路径。**
6. **敏感文件零容忍**：仓库是 public；证件/报名表/token 绝不入库。
